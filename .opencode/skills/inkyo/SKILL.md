# Inkyo — Ukiyo-e Japan Trip Map

Inkyo (印経 / "travel journal") is a personal, local-first trip-planning web app:
an illustrated ukiyo-e map of Japan with saved places/reels from Google Maps and
Instagram, plus a drag-and-drop day planner and ICS export. Chrome is
Apple-minimal and modern; read the `modern-ui` skill for all UI work.

The map is a **shared public map**: anyone (even logged out) can view, add, and
manage places and reels. Supabase is the shared source of truth; Dexie is the
offline cache. There is no per-user scoping and no moderation.

## North-star constraints

1. **Modern, clean UI; readability first.** Read `.opencode/skills/modern-ui/SKILL.md`.
   The map is the hero, chrome floats and collapses, and the ukiyo-e aesthetic
   must never compromise label contrast, road legibility, or pin visibility.
   When in doubt, mute the decoration, not the text.
2. **Local-first, shared data.** IndexedDB (Dexie) caches the map and works
   offline. Supabase is the shared source of truth; writes auto-publish (~1s
   debounce) and the app pulls public changes on load/focus.
3. **Free forever.** Target $0/month: Cloudflare Pages (app) + Supabase free
   tier (data/auth). No paid APIs. Tiles are OpenFreeMap public. R2 optional.
4. **No backend secrets in the client.** Only the Supabase anon key is public.
   Access is intentionally open; see `supabase/migrations/0002_shared_map.sql`.

## Ukiyo-e design system

All tokens live in `src/design/tokens.ts`; CSS variables are generated by
`src/design/theme.tsx`. Never hardcode colors in components. The UI chrome uses
neutral Apple-style roles (canvas/surface/text/accent) with a single accent;
the map keeps the woodblock palette below.

```
sumi   #1a1a1a   ink, primary text, outlines
indigo #1b3a5c   water, primary brand, headers
beni   #c1352f   accents, seals, active state, markers
ochre  #c98a3b   highlights, labels, roads
washi  #f4ecd8   background, label halos, cards
matcha #6b7f4e   land/parks secondary
ai     #22304a   deep water
```

Type: system SF stack for UI (`--font-ui`); `Shippori Mincho` reserved for
display/brand accents. Textures: washi grain overlay (subtle, toggleable).
Components live under `src/components/ui/` (e.g. `Icon`) and follow the
`modern-ui` specs (buttons, inputs, segmented control, list rows, empty state).

### Map style rules
- Labels: washi `#f4ecd8` halo (>=2px), dark ink text, min-zoom gates so the map
  is never cluttered. House numbers and minor POIs suppressed at low zoom.
- Water: indigo/`ai` fills; land washi/ochre; greens desaturated toward matcha.
- Roads: ochre -> beni ramp by class, casing in ink; keep high contrast.
- **Japan focus.** The map fits all of Japan on load (bounds, not a fixed zoom)
  and masks neighboring countries with a flat muted fill above base detail, so
  their roads/labels disappear. Mask data is generated by
  `tools/map/build-japan-mask.mjs` into `src/map/japan-foreign-mask.json`.

## Basemap + tiles

- Default vector source: **OpenFreeMap public instance** (free, no key):
  `https://tiles.openfreemap.org/styles/{positron|liberty|bright|dark|fiord}`.
  We fork the style JSON and restyle; we do not depend on their hosted style at runtime.
- Fallback: **Protomaps PMTiles** file (`https://demo-bucket.protomaps.com/v4.pmtiles`
  for dev) via `pmtiles://` protocol, or self-hosted extract on R2.
- Custom illustrated tiles: raster/PMTiles on R2, added as an overlay source above
  the vector base but below labels. See `docs/tiles-pipeline.md`.

## Data model

See `docs/data-model.md`. Tables: `places`, `reels`, `trips`, `days`,
`itinerary`. Every row has `id` (uuid), `user_id` (nullable), `updated_at` (ISO),
`deleted_at` (soft delete). Local Dexie mirrors these exactly.

Sync strategy: writes enqueue in an `outbox` and `schedulePublish()` flushes
them, then `pullShared()` merges remote changes by `updated_at` (last-write-wins)
**including soft-deleted rows** so deletions propagate. The map is public and
open to anonymous read/write (`supabase/migrations/0002_shared_map.sql`).

## Importers

- **Add place (primary).** `src/components/AddPlacePanel.tsx`: paste a Google
  Maps or Instagram link, or raw `lat, lng`. `src/data/linkParser.ts` detects the
  source and extracts coordinates/name; optional Nominatim place search fills
  coords. Saving stores the link in `source_url`.
- **Bulk import (advanced, behind a disclosure).** Google Takeout
  (`docs/takeout-import.md`) and Instagram (`docs/instagram-import.md`) importer
  panels remain available in the "import" tab.
- **Google Takeout**: `Saved Places.csv` has `Title,Note,URL,Comment` with no
  coords; coords are extracted from the Maps URL (via `linkParser`), else
  geocoded via Nominatim. `Labeled Places.json` is already GeoJSON.
- **Instagram**: `saved_posts.json` only yields account + permalink + timestamp;
  offer a "pin to map" queue. Never scrape media.

## Deployment

Cloudflare Pages: build `npm run build`, output `dist`. Set `VITE_SUPABASE_URL`
and `VITE_SUPABASE_ANON_KEY` as Pages env vars. R2 bucket for tiles behind a
custom domain/CORS. See `docs/deployment.md`.
